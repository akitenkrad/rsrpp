# アーキテクチャ

1 回のパースは poppler を 4 回呼ぶ — ページの寸法を得る `pdfinfo`，ページごとの画像を作る
`pdftocairo`，座標つきのテキストを得る `pdftohtml -xml`，そして同じテキストをもう一度別の
読み方で取る `pdftotext` — そのうえで，どの行が本文で，どれがキャプションで，どれが節見出しか
を，幾何情報だけから判定する．LLM は任意であり，ある判断の唯一の根拠になることはない．

## コアモジュール

- **`parser`**: PDF パースの中核
  - Poppler を使った PDF から HTML への変換
  - HTML 構造のパースとページオブジェクトの生成
  - 節構造の抽出

- **`models`**: データ構造の定義
  - `Word`: 単語単位の情報（座標，フォントサイズなど）
  - `Line`: 行単位の情報と単語の集合
  - `Block`: ブロック単位の情報と行の集合（`BlockType`: Body, Caption, Header を持つ）
  - `Page`: ページ単位の情報とブロックの集合
  - `Section`: `contents`・`math_contents`・`captions` フィールドを持つ節の構造
  - `RichText`: 元のテキストと数式マークアップ版の両方を持つテキスト
  - `fix_suffix_hyphens`: 複合語のためのテキスト正規化（例: "databased" → "data-based"）

- **`cleaner`**: テキストのクリーニングとブロックの分類
  - 図表キャプションの検出（例: "Figure 1:", "Table 2."）
  - ブロック種別の分類（Body, Caption, Header）

- **`llm`**: LLM による処理の強化と数式の検出
  - Unicode のパターン・構造的ヒューリスティック・文脈解析による数式検出
  - LLM による数式抽出と，trigram によるテキストブロックへの対応付け
  - 誤検出のフィルタリング（日付，統計，節の参照）
  - `<math>...</math>` 出力を統一するための Unicode から LaTeX への変換
  - LLM による節の検証

- **`extracter`**: 図表の抽出
  - OpenCV を使った図の検出
  - 表領域の特定と除外（誤検出を弾くための面積の上限つき）
  - テキスト領域が退化した場合の検出と，ページ全体へのフォールバック

- **`converter`**: フォーマット変換
  - ページから節への変換
  - 節の検出と，非標準の書式に対するフォールバック（アンカー語の照合）
  - poppler の呼び出しすべてを囲む監視機構と，そこから上がる型付きのエラー
  - JSON 出力の生成

- **`config`**: 設定の管理
  - パーサ設定の管理
  - パースが作業する一時ディレクトリと，その寿命
  - 数式テキストの対応表の保持

- **`tempdir_sweep`**: 強制終了された実行が残した作業ディレクトリを，プロセスにつき 1 回，
  所有プロセスが消えたと確実に言える場合にかぎり回収する

## 節見出しをどう判定するか

フォントサイズだけでは，節見出しと，同じサイズで組まれた小図のタイトルを区別できない．そして
偽の見出しは単なるノイズでは済まない — それに続く本文を丸ごと飲み込むので，本来の節がその
テキストを失う．そこで 2 つのパスを使う．

**フォントのパス**は，見出し用のフォントで組まれた文字列をすべて集める．続く**配置のパス**は，
候補それぞれがページのどこに座っているかを問う．見出しはページに対して応答する — アンカー語，
段の余白，段の中央，番号付き見出しが共有するインデント．そのいずれにも応答しない候補は棄却
される．

配置のパスには 2 つの安全弁があり，どちらも 2,812 本の論文からなるコーパスで測ったうえで
残されている:

- 候補が 5 個未満のときはパス自体を走らせない．レイアウトを読み取れるだけの分量がその論文から
  見えておらず，判定を 1 つ誤ればそれがその論文の節の大きな割合を占めてしまう．
- 判定の結果，候補の半分以上を棄却することになる場合は，パス全体が引き下がる．規則と文書が
  レイアウトについて食い違っているのであり，権威は文書の側にある．

どちらを緩めても，偽の見出しは 1 つも減らず，実在する見出しを失う．

## CLI ツール

`rsrpp-cli` は独立したバイナリで，コマンドライン引数のパース，ログ出力，JSON の書き出し，
そして [終了コード](cli.ja.md#終了コード) を担う．終了コードは，バッチ実行が「見込みの無い
文書」と「壊れた環境」を区別するためのものである．
