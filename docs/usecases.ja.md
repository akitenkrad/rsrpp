# 何のためのものか

RSRPP があるのは，論文の PDF を *テキスト* として読むだけでは足りないからである．読み順に
並んだ文字の山からは，どこまでが導入でどこからが付録なのかが失われ，図の軸ラベルが議論の中に
紛れ込み，表のセルが文の途中に貼り付く．このパーサの仕事は，PDF が持っていてテキスト抽出が
捨ててしまった構造を返すことにある．

## 論文をノートにする

出力は 1 節につき 1 エントリで，それぞれが自分の本文と，その節に含まれる図表のキャプションを
持つ．これは「論文 1 本につき 1 ノート，節ごとに見出し」という形にそのまま対応する．読んだ
論文のアーカイブを，打ち直さずに埋めていく — このパーサはそのために作られた．

```bash
rsrpp --pdf "https://arxiv.org/pdf/1706.03762" --out attention.json
```

## 検索インデックスに流し込む

論文を文字数でチャンクに切ると，議論の途中で切れる．節で切ればそうはならないし，どのチャンクにも
ベクトルと一緒に保存する価値のあるタイトルが付く．`contents` からはキャプションと表のセルが
すでに除かれているので，チャンクの中身は「軸ラベルの混ざった散文」ではなく散文そのものになる．

## コーパス単位で回す

このパーサは論文 1 本ではなく数千本に向けて使うことを前提に作られている．失敗時の振る舞いが
これほど具体的に決められているのはそのためである．いつまでも終わらない文書は打ち切られ，
バッチが飛ばせるように [専用の終了コード](cli.ja.md#終了コード) で報告される．ある論文の
一時ファイルが次の論文の足を引っ張ることはない．そしてどのパースも，元テキストのうちどれだけを
保持したかを申告するので，静かに壊れた論文は出力を diff しなくても見つかる．

## 数式を読む

PDF の中の数式は，Unicode の記号と ASCII の慣習と画像の混合物である．RSRPP は見つけたものを
`<math>...</math>` で囲み，LaTeX へ統一する．下流のツールが目にする記法は 3 種類ではなく
1 種類になる．[出力フォーマット](output.ja.md#数式のマークアップ) を参照．

## これは何ではないか

- **OCR エンジンではない．** テキストレイヤを持たないスキャン画像のページからは何も得られない．
  先に OCR をかけること．
- **レイアウト忠実なコンバータではない．** 出力は構造化されたテキストであって，ページの
  再現ではない．
- **LLM に依存していない．** LLM を通す経路は数式の抽出と節の検証を改善するが，構造に関する
  判断にはすべて幾何的な裏付けがあり，`--no-llm` はサポートされた動かし方である．
