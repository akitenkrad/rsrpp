# テスト

ユニットテストと E2E テストは分けてある．かかる時間が 3 桁違うからである．LLM を有効にした
パースは約 176 秒，同じパースを LLM 無しで行うと約 2.9 秒，ユニットテストは全部合わせて
約 2 秒である．

```bash
# ユニットテストのみ（約 2 秒）— 作業中に回すのはこれ
makers nextest

# E2E: PDF を取得し，poppler と OpenCV を動かし，OpenAI API を呼ぶ
makers nextest-e2e

# doc テストも含めてすべて — コミット前に回す
makers nextest-all

# 単一のテスト
makers nextest test_parse_extract_sections_1

# cargo-make を使わない場合
cargo nextest run --workspace
```

E2E テストは arXiv からサンプル論文をダウンロードしてキャッシュする（TTL は
`RSRPP_TEST_CACHE_TTL_SECONDS` で指定，既定 24 時間）．いくつかは OpenAI API を呼ぶので，
それらが意味のある動作をするには `OPENAI_API_KEY` が設定されている必要がある．構造を検証する
テストは LLM を無効にしてパースする．LLM 経路には専用のテストが別にある．

## コーパスで変更を測る

テストが通ることは，パース規則への変更の完了条件ではない．テストが覆うのは誰かが思いついた
ケースであり，実在の論文からなるコーパスが覆うのは，誰も思いつかなかったケースである．この
パーサが起こした最悪の退行のうち 2 つ — ページの余白に押されたスタンプが最初の節になってしまう
もの，そして途中で段組みが変わる文書 — は，テストからも 300 本のサンプルからも見えず，
コーパス全体で回してはじめて姿を現した．

[`tools/ab-harness/`](../tools/ab-harness/README.md) は，同じ PDF の集合に対して 2 つの
ビルドを走らせ，何が動いたかを報告する．変化した節のリスト，下がったカバレッジ，テキストが
短くなった論文である．コーパスは各自で用意すること．このリポジトリは論文ファイルも，その
置き場所も一切同梱していない．
